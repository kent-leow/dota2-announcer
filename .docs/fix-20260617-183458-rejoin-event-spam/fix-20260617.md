## Changelog

Added loadSchedule re-initialization on state change to in-match in MainDock.tsx to properly seed firedIds with the correct game time on rejoin.

## Root Cause

When joining an ongoing game, the event scheduler had no knowledge of which events had already passed. The timer would sync to the actual game time (e.g., 20 minutes), and `tick()` would see all events from 0 to the current time as unfired, announcing them all at once.

Two issues combined:
1. `loadSchedule` was only called on component mount (potentially with stale/zero elapsed time)
2. `tick()` had no guard against announcing events that were due far in the past

## Fix

1. **eventScheduler.ts**: Added `ANNOUNCE_WINDOW_MS = 60_000` constant. In `tick()`, events are only announced if `elapsedMs - fire.fireAtMs <= ANNOUNCE_WINDOW_MS`. Events older than 60s are silently marked as fired without triggering audio.

2. **MainDock.tsx**: Added `loadSchedule(config, ms)` call when state changes to `in-match`, ensuring the scheduler is properly initialized with the current game time on rejoin.
